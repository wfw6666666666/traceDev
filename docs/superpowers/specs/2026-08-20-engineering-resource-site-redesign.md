# TraceDev 工程资料站视觉改版设计

日期：2026-08-20  
状态：待确认  
方向：A — 工程资料站

## 1. 改版目标

把 TraceDev 从常见的 AI 生成式“卡片展示站”，调整为克制、可靠、方便查找的工程资料站。

改版不改变现有核心功能：教学视频、咸鱼店铺、资料下载、学习日志、疑难解答、关于作者、主题切换和管理员操作仍然保留。此次重点是重新定义页面布局和视觉语法，使用户能更快识别内容类别、资源状态和可执行操作。

成功标准：

- 首屏看起来像长期维护的个人技术资料站，而不是 SaaS 落地页模板。
- 页面不再依赖大圆角卡片、发光、渐变、悬浮抬升和图标底座建立层级。
- 关键操作与普通操作在视觉上有明确差异。
- 桌面端信息密度提高，移动端保持清晰可点按。
- 现有数据结构、下载逻辑、日志管理逻辑和标签页切换不被破坏。

## 2. 设计原则

### 2.1 信息优先

标题、元数据、描述和操作按照阅读顺序排布。装饰不能比内容更醒目。资源列表优先展示名称、类型、更新时间、大小和操作，不使用同权重的卡片矩阵制造视觉噪声。

### 2.2 少卡片化

只有具备独立边界的复杂内容使用容器。普通资源、FAQ、导航项和筛选项使用分隔线、留白、文字层级和背景变化区分，不再为每个项目加完整边框和阴影。

### 2.3 操作分级

- 主操作：实心砖橙按钮，仅用于下载、保存、登录、发布等确定性动作。
- 次操作：细边框按钮，用于复制、筛选、上传、设置等辅助动作。
- 轻操作：文字链接或图标按钮，用于查看详情、关闭、编辑、返回顶部等低权重动作。
- 危险操作：白底/透明底配红色文字和边框，不使用大面积红底。

按钮采用 4px 圆角，不使用胶囊按钮。按钮默认无阴影，按下时仅改变背景和位移 1px，不缩放。

### 2.4 工程感而非赛博感

工程感来自网格、编号、元数据、等宽数字、清晰分隔和准确文案，而不是霓虹色、发光边框和黑色渐变。

## 3. 信息架构

维持单页标签面板结构，避免改动现有交互逻辑。

页面骨架：

1. 顶部站点栏
2. 栏目导航
3. 当前栏目标题与简短说明
4. 筛选或栏目辅助信息
5. 主要内容列表
6. 页脚和站点状态信息

桌面端顶部采用两层感知、一层实际结构：左侧是品牌和一句简短定位，中间是纯文字栏目导航，右侧是主题与管理入口。移动端保留品牌栏，通过菜单按钮展开纵向栏目列表。

不新增首页 Hero、功能卖点区、统计大卡片或宣传式 CTA。

## 4. 视觉系统

### 4.1 色彩

浅色主题为默认主题：

- 页面背景：`#f3f0e9`，略带纸张暖色。
- 主内容背景：`#fbfaf7`。
- 强调区域背景：`#ebe6dc`。
- 主文字：`#242321`。
- 次文字：`#625f59`。
- 弱文字：`#8a857c`。
- 默认边框：`#d8d2c7`。
- 强边框：`#aaa297`。
- 品牌强调：`#a44725`。
- 品牌强调 hover：`#84381f`。
- 成功：`#356646`。
- 危险：`#a33a32`。

深色主题：

- 页面背景：`#191816`。
- 主内容背景：`#211f1c`。
- 强调区域背景：`#2b2824`。
- 主文字：`#efebe3`。
- 次文字：`#c2bbb0`。
- 弱文字：`#8f887d`。
- 默认边框：`#3b3731`。
- 强边框：`#5a534a`。
- 品牌强调：`#cf7149`。

页面不使用大面积渐变、环境光晕或彩色发光。图片占位区域使用纯色或细网格纹理。

### 4.2 字体

- 中文正文：`Inter, "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`。
- 栏目大标题：Georgia 与中文宋体回退，用于建立资料出版物气质。
- 文件大小、日期、版本、提取码：`JetBrains Mono, Consolas, monospace`。

标题不过度加粗。正文与元数据通过字号、颜色和间距区分，不依赖大量彩色标签。

### 4.3 尺寸与圆角

- 页面最大宽度：1120px。
- 内容区桌面左右留白：32px；移动端：16px。
- 栏目上下间距：40–48px。
- 普通组件圆角：4px。
- 图片和复杂内容容器圆角：6px。
- 模态框圆角：8px。
- 圆形只用于头像、状态点和必须为圆形的图标控件。

### 4.4 边框和阴影

默认使用 1px 边框或分隔线。卡片不默认投影。仅导航吸顶、模态框和浮层允许极轻的阴影。Hover 不抬升卡片，不改变图片比例，不显示渐变装饰线。

## 5. 核心组件设计

### 5.1 顶部导航

- 导航栏背景为不透明或近似不透明纸色，滚动后增加底部分隔线。
- Logo 与 TraceDev 文字组合保留，增加小号站点定位“嵌入式学习与资料归档”。
- 桌面导航使用纯文字；激活项以深色文字、底部 2px 砖橙线表示。
- 导航图标默认移除，避免六个图标同时竞争注意力。
- 管理入口保持低可见度；主题切换采用无边框方形图标按钮。

### 5.2 栏目标题

- 左对齐，不再居中。
- 取消标题下方短装饰线。
- 标题与描述处于同一信息块，可在右侧显示内容数量或更新时间。
- 每个栏目标题上方可使用小号编号，例如 `01 / VIDEOS`，形成可控的工程归档感。

### 5.3 教学视频

桌面端仍可保持两到三列，但卡片改成媒体条目：缩略图、标题、描述与时长直接排列。容器只使用底部分隔线；播放图标改成缩略图左下的小实心方形标记，不使用大圆形播放按钮。

Hover 仅改变标题颜色和缩略图透明度，不移动整张内容。

### 5.4 咸鱼店铺

采用横向商品条目：左侧商品图，中间名称、简介和状态，右侧价格与“去闲鱼查看”。桌面端突出商品信息，移动端改为图片在上、信息在下。

价格使用等宽数字和品牌色，但字号不过度放大。外链操作使用文字箭头或窄实心按钮。

### 5.5 资料下载

这是改版的核心区域，桌面端采用接近文件目录的列表结构：

- 文件类型图标或扩展名
- 资源名称与简短说明
- 分类
- 文件大小/版本/更新时间
- 下载操作

列表项之间使用分隔线，Hover 仅增加浅色行背景。移动端将元数据折到标题下方，下载按钮保持可直接点击。

分类筛选改为方角文本筛选项。激活项使用底色与边框，不使用圆角胶囊。

### 5.6 学习日志

文章列表改成期刊目录样式：日期位于固定宽度左栏，标题与摘要位于主栏，标签和附件数量作为弱元数据。移除每篇文章的独立浮动卡片效果。

管理员操作栏采用简单工具栏，不使用彩色大容器。AI 设置和 AI 整理仍然保留，但视觉权重低于新建和保存。

### 5.7 FAQ

FAQ 使用连续列表和横向分隔线。问题行可点击，右侧使用 `+` / `−`，不使用卡片边框和旋转箭头。展开内容与问题正文左侧对齐。

### 5.8 关于作者

采用两栏简历式布局：左侧简介和联系方式，右侧经历、方向和技能。删除百分比技能进度条；改为技术方向列表或“常用/熟悉/正在学习”的文字分组，避免简历模板感。

### 5.9 模态框与表单

- 移除 `rounded-2xl`、重阴影和明显背景模糊。
- 模态框使用 8px 圆角、清晰边框和短标题栏。
- 表单输入框采用 4px 圆角，聚焦时显示 1px 品牌边框和轻微外环。
- 复制按钮显示“复制”文字或明确图标提示，不只依赖图标。
- 保存、登录、下载是实心主按钮；取消、关闭和设置是次级按钮。

### 5.10 页脚

页脚通过顶部细线与内容分隔，保持紧凑。版权、备案、邮箱和访问统计组成一行或两行，不做卡片容器。

## 6. 动效与交互状态

- 标签页切换：150–200ms 淡入，不做从下方大幅进入。
- 按钮 hover：颜色变化；active：向下 1px。
- 列表 hover：背景色变化。
- FAQ：高度与透明度过渡，时长 180–220ms。
- 模态框：淡入与 4px 位移，不使用缩放弹出。
- 图片 hover：最多轻微降低亮度，不缩放。
- 尊重 `prefers-reduced-motion`。

所有可交互元素必须有 `focus-visible` 状态。颜色不能是激活状态的唯一表达，导航、筛选和表单同时使用线条或边框。

## 7. 实施边界

主要修改：

- `index.html`：调整导航、栏目标题、模态框和静态容器的结构及类名。
- `css/style.css`：重建色彩变量、导航、按钮、列表、卡片、FAQ、表单和响应式样式。
- `js/app.js`：调整动态生成的视频、商品、资源、FAQ、关于作者标记结构。
- `js/journal.js`：调整日志列表与详情页动态模板类名，不改变保存、上传和鉴权逻辑。
- `DESIGN.md`：实施完成后同步当前视觉规范，避免旧规范与代码矛盾。

不在本次范围：

- 不更换后端或数据格式。
- 不重写 GitHub 日志保存功能。
- 不新增账户系统、搜索后端或资源数据库。
- 不照搬参考站的代码、品牌或具体视觉资产。
- 不增加大型 Hero、轮播图、营销弹窗和装饰动画。

## 8. 响应式策略

### 桌面端（≥ 1024px）

使用 1120px 内容宽度。资源和日志优先采用横向列表，商品使用左右布局，导航完整显示。

### 平板端（768–1023px）

适当隐藏次要元数据，视频保持两列，商品横向布局缩窄。

### 移动端（< 768px）

导航折叠为菜单。所有内容转为单列，列表操作移到内容底部或右侧固定区域。按钮最小点击高度 40px，文本不得因强制单行而溢出。

## 9. 验证方案

实施后进行以下检查：

- 使用本地 HTTP 服务打开站点，检查页面资源无 404。
- 验证六个标签面板切换、主题切换、移动端菜单和返回顶部。
- 验证视频、商品、下载资源、FAQ、关于作者和日志内容正确渲染。
- 验证下载弹窗、复制按钮、登录弹窗、AI 设置、日志编辑与详情弹窗仍可打开和关闭。
- 检查 1440px、1024px、768px、390px 四种宽度。
- 检查浅色与深色主题的文字对比度、焦点状态和按钮层级。
- 检查控制台错误和页面横向溢出。

## 10. 最终视觉判断标准

如果某个组件仍然同时具备“大圆角、彩色半透明底、描边、阴影、图标和位移动效”中的三项以上，应继续简化。

页面最终应呈现为：一个个人长期维护的嵌入式技术归档站，安静、紧凑、可信，带有适度纸张与工程文档气质，而不是一个生成式 AI 套用的产品宣传模板。
